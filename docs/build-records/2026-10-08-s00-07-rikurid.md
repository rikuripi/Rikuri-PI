  - Real path through the CLI and socket: `init` → ok; `task create` → ok; the same key again → the stored response with `"replayed": true`; the same key with a changed title → `idempotency_conflict`, exit 3.
  - **Defect A:** `state show` hangs the daemon: on a fresh home, `init` then `state show` → no response, client `daemon_unavailable` after its 30 s timeout (`os error 11`), and every later request hangs too. The daemon is single-threaded and waiting on a futex. Cause (code reading): `Kernel::state` runs inside `Store::read`, which holds the store's connection `Mutex`, and calls `Store::schema_version`, which locks the same non-reentrant `Mutex`. The bug predates today's storage changes (`schema_version` locked the connection on 2026-10-05 too); the command was never run.
  - **Defect B (code reading):** `server::bind` creates the socket directory 0700 only when it is missing; an existing directory with a looser mode is accepted although the server documents an owner-only directory, and the socket exists with the umask's mode between `bind` and its `chmod 0600`. Same class as the storage owner-only defect fixed in PR #18.

- [x] Sibling sweep done: in `rikurid` the only `Store` call inside a transaction closure is `Store::now` (clock only, no lock), so it is not refused; `system.health` and `check_consistency` call the store outside closures. Files and directories `rikurid` creates: the socket directory (now checked), the socket (0600 after bind, inside the owner-only directory), and the database (through `Store::open`).
- [x] Root-cause class (A): **a lock re-entered through the store's own API inside its transaction closure.** `Store` methods that lock the connection (`read`, `write`, `schema_version`) must never be called from inside `read`/`write`; with a non-reentrant `Mutex` the result is a silent hang, which Law 1 forbids. Sibling sweep: every `self.store.*` call inside a `read`/`write` closure in `rikurid` (done, line above), and a tripwire in `rikuri-storage` so a re-entrant call returns an error instead of deadlocking.
- [x] Root-cause class (B): a guarantee stated more broadly than its mechanism (owner-only only when the directory is created), the class fixed in storage in PR #18. Sibling sweep: every file or directory `rikurid` creates (socket, socket directory; the database goes through `Store::open`).
- [x] Round 2 root-cause classes: **health evidence that its own check overwrites** (the consistency read reset the failure count it was about to report), swept to every place health is computed from shared counters (store aggregate, read/write split; the consistency component records its own replay, which is what it reports); **a destructive cleanup that trusts the path's name** (`remove_file` on whatever sits at the socket path), swept to every `remove_file`/`remove_dir` in the workspace (only this one); **a single-writer promise without a lock**, swept to the store (the only writer of the database).
