### Design

The new branch, after `any(`/`all(` (written once, `ML` in `rule_ml.py`):

```text
(?=(?P<m>(?:[^\[\]]*?(?:,|(?<!not)\())??\s*test(?=\s*[,)])))(?P=m)[^\[\]]*\)
```

followed by the rule's `\s*\)\s*\]`.

- **What it accepts.** A `test` that is the first item (white space and line breaks before it), or follows a `,` or a `(` that is not `not(`, anywhere before the attribute's next bracket, followed by `,` or `)`; and the attribute's first bracket after it is the `]` closing `))`. So `not(test)` is never a marker, split over lines or not, and a `test` past the `]` (in the item below) is never read.
- **Why the first `test` is enough (commit).** Between the first candidate and any later one there is no bracket, so the first bracket after each is the same one: if a later candidate's tail matches, the first one's does. The lookahead finds the first candidate (`??` tries the start first, then each `,`/`(` in order through `*?`), and the backreference consumes it; Python never backtracks into a lookahead.
- **Why it is linear.** Every scan in the branch (`[^\[\]]`) stops at the next `[` or `]`. Every marker begins with `#[`, so a marker's scan ends at or before the next marker's `[`: no text is scanned for two markers, and inside one, each piece of white space is scanned from the one `,`/`(` or `)` before it.
- **Limits, unchanged from the old rule or by design** (verifier round 1): a `[` or `]` inside a comment or string within a marker ends the scan, and a comment just before `test` (`// c` on the line above it, `any(/* c */ test)`) hides it, so such a marker is not seen (none on this machine; old rule the same; in the follow-up's row below). `not (test)` with a space, or a line break before `(`, counts as a marker, as the old rule already did on one line: it only locks more, and `cargo fmt --check` (gate step `format`) refuses that spelling here.
- **Old matches kept.** The branch is a new alternative beside the two existing ones, `(?:(?:A|B).*\)|ML)`, so every match of the old rule is a match of the new one. A single-line marker the old branches miss (a bracket inside it) is matched by them as before.
- **The tripwire** gets the same branch beside `test`. With `^[ \t]*` (the rule's start class is wider), wherever `RUST_INLINE_TEST` matches, the rule's `starts_at` matches at the same place: the tripwire never names a file this repository's rule covers (`corpus-py314.out`: no such place in 40,059 files).

**Behaviour changes to expose:** (1) the fix-lock now covers tests under a marker written over several lines, and such a marker itself; none exist here today. (2) `fix-lock on` (both repositories) names tracked `.rs` files whose `cfg(any(test, …))` / `cfg(all(test, …))` markers, on one line or several, no rule covers; here none (every one is covered), and rikuripi/rikurinode tracks no `.rs` file at `97a2a8b` and has no `inline_tests` rule, so when it gains Rust it is named for these markers as it already would be for `#[cfg(test)]`. (3) A heuristic kept from the old rule: a `test` nested under `not(all(…, test))` is still taken for a marker (on the safe side: more is locked; 1 of the 1,097 places only the new tripwire matches, ahash-0.8.12 `random_state.rs`, `not-nested.out`).
